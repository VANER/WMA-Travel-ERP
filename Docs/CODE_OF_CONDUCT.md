# Código de Conduta

**Projeto:** WMA Travel ERP
**Versão:** 1.0.0
**Última atualização:** 29/07/2026

---

## Objetivo

O **WMA Travel ERP** é um projeto desenvolvido para promover qualidade técnica,
colaboração, profissionalismo, ética e respeito entre todos os participantes.

Este Código de Conduta estabelece os princípios de comportamento esperados
durante todas as atividades relacionadas ao projeto.

Aplica-se às seguintes áreas:

- Desenvolvimento de software.
- Banco de dados.
- Documentação.
- Testes.
- Revisões de código.
- Gestão do projeto.
- Comunicação técnica.
- Manutenção da infraestrutura.

Todos os colaboradores, parceiros e contribuidores devem seguir estas diretrizes.

---

## Valores do Projeto

O projeto é guiado pelos seguintes valores:

- Respeito.
- Ética.
- Transparência.
- Colaboração.
- Responsabilidade.
- Profissionalismo.
- Melhoria contínua.
- Compartilhamento de conhecimento.
- Qualidade técnica.
- Inovação.

---

## Comportamentos Esperados

Todos os participantes devem:

- Agir com respeito e cordialidade.
- Colaborar de forma construtiva.
- Aceitar críticas técnicas fundamentadas.
- Documentar adequadamente suas contribuições.
- Compartilhar conhecimento.
- Respeitar os padrões arquiteturais.
- Preservar a qualidade do código.
- Manter postura profissional em todas as interações.

---

## Colaboração

Toda contribuição deve buscar:

- Simplicidade.
- Reutilização.
- Padronização.
- Segurança.
- Desempenho.
- Escalabilidade.
- Facilidade de manutenção.
- Governança dos dados.

As decisões técnicas devem ser baseadas em critérios objetivos e registradas quando relevantes.

---

## Revisão de Código

Durante o processo de revisão:

- Critique o código, nunca a pessoa.
- Apresente sugestões fundamentadas.
- Explique alterações relevantes.
- Mantenha comunicação respeitosa.
- Incentive melhorias contínuas.
- Preserve a consistência do projeto.

O objetivo do **Code Review** é elevar continuamente a qualidade técnica do sistema.

---

## Condutas Inaceitáveis

Não serão aceitos:

- Assédio.
- Discriminação.
- Intimidação.
- Ameaças.
- Linguagem ofensiva.
- Ataques pessoais.
- Divulgação de informações confidenciais.
- Sabotagem do projeto.
- Exposição indevida de colaboradores.
- Qualquer conduta incompatível com um ambiente profissional.

---

## Qualidade Técnica

Todo desenvolvimento deve seguir:

- Clean Code.
- SOLID.
- Clean Architecture.
- Domain-Driven Design (DDD).
- Padrões definidos no `CONTRIBUTING.md`.
- Convenções técnicas do projeto.
- Boas práticas de segurança.

---

## Banco de Dados

Toda alteração estrutural deverá:

- Possuir script versionado.
- Ser documentada.
- Preservar a integridade referencial.
- Manter compatibilidade quando aplicável.
- Possuir plano de rollback quando necessário.
- Passar por revisão antes da integração.

É proibida qualquer alteração manual em ambiente de produção sem processo formal de aprovação.

---

## Segurança da Informação

Todos os participantes devem proteger informações confidenciais.

É proibido:

- Compartilhar senhas.
- Divulgar credenciais.
- Expor chaves privadas.
- Publicar dados sensíveis.
- Utilizar informações internas para fins não autorizados.

Sempre que possível, devem ser utilizados:

- Variáveis de ambiente.
- Gerenciamento seguro de segredos.
- Controle de acesso adequado.

---

## Uso do Repositório

Os colaboradores devem:

- Utilizar branches apropriadas.
- Seguir o padrão de commits.
- Manter documentação atualizada.
- Remover código obsoleto quando necessário.
- Evitar duplicação de código.
- Executar testes antes da integração.

---

## Comunicação

A comunicação deve permanecer:

- Respeitosa.
- Objetiva.
- Técnica.
- Organizada.
- Colaborativa.

Discussões devem concentrar-se em soluções técnicas e na evolução do projeto.

---

## Responsabilidades

Cada colaborador é responsável por:

- Compreender a arquitetura do projeto.
- Seguir os padrões estabelecidos.
- Preservar a qualidade do código.
- Reportar problemas identificados.
- Contribuir para melhoria contínua do ERP.

---

## Resolução de Conflitos

Caso ocorra qualquer conflito relacionado ao projeto:

1. Buscar diálogo respeitoso entre as partes.
2. Apresentar fatos de forma objetiva.
3. Envolver o responsável técnico quando necessário.
4. Documentar decisões relevantes.

Sempre que possível, as decisões devem ser fundamentadas em critérios técnicos.
